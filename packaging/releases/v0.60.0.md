## Self-updating weather app

- Daily, quiet release checks in the app and Omarchy bar, with a manual **Check for updates** action.
- Installed and available versions with **Update and restart**: verified downloads, clean effects shutdown, bar refresh, and reopening the latest app.
- Saved location, units, settings, and bar placement retained. Previous runtimes are kept, with failed-startup rollback and interrupted-update recovery.
- The 10-day forecast now appears directly below the hourly forecast.

## Existing users: one-time migration

Older apps cannot gain the new controls just by being reopened.

For an existing Omarchy installation, update the plugin once:

```sh
omarchy plugin update a-weather-app.weather
```

Then right-click the weather widget and choose **Update and restart**. The updated bar can upgrade an older runtime even when that old app has no updater. Once reopened, confirm **0.60.0** under **Settings → Application**. If you already updated the plugin, start with the bar action.

If you configured the widget's `projectPath` directly to an extracted runtime, set it to your installed plugin folder for this migration. Keep your saved state directory and bar placement.

Older standalone users should quit the old app, download and verify this package, extract it into a new directory, and launch the new executable once. Update any shortcut that still points to the old directory. Future published updates use the in-app controls.

Read the [installation and migration instructions](https://github.com/joega/a-weather-app#one-time-bootstrap-for-existing-installations). New Omarchy installations still require the initial verified runtime setup described in the README. Routine updates require no administrator privileges.

The updater waits for the repository's supported release pin. Immediately after publication, allow the pin update to finish before migrating. Local edits, custom plugin branches, and linked development checkouts are preserved.

Linux x86_64 package for Omarchy. Verify the archive against `SHA256SUMS` and the committed repository pin before extracting. `go-runtime.json` records the source revision and runtime inventory.
